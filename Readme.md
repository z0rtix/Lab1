## 1. Постановка задачи

### 1.1. Что делается в работе (идея)
В этой лабе я написал самобалансирующееся бинарное дерево поиска (АВЛ-дерево) без использования контейнеров STL, управляя памятью вручную. Поверх этого дерева реализован абстрактный тип данных «Множество» (`Set`). 

### 1.2. Зачем это нужно
Обычное бинарное дерево при добавлении заранее отсортированных данных (например, чисел 1, 2, 3, 4...) вырождается в связный список, и поиск в нём замедляется до $O(N)$. АВЛ-дерево решает эту проблему: оно автоматически балансирует свои ветви при вставке и удалении, гарантируя, что высота дерева всегда будет логарифмической. Это нужно для задач, где критически важен стабильно быстрый поиск уникальных записей (например, база студентов по ID).

## 2. Сущности прикладной задачи

### 2.1. Описание сущностей
1. **Элемент / Ключ (`T`)** — то, что мы храним. Может быть числом, а может быть сложным объектом.
2. **Множество (`Set`)** — контейнер, в котором хранятся только уникальные элементы (без дубликатов).
3. **Удостоверение личности (`PersonID`)** — составной ключ из серии и номера паспорта. По нему мы упорядочиваем людей.

## 3. Архитектура

### 3.1. Компоненты системы
Проект разбит на 4 слоя:
1. **Интерфейс (UI):** `menu.cpp` — консольное меню для взаимодействия с пользователем и графической отрисовки дерева.
2. **Ядро структуры данных:** `AVLTree.hpp` (отвечает за физическое хранение, балансировку и узлы) и `Set.hpp` (отвечает за математическую логику множеств).
3. **Предметная область:** `Person.hpp` (структуры людей для проверки универсальности шаблона).
4. **Тесты и бенчмарки:** `tests.cpp` (12 блоков проверки + контроль утечек) и `benchmark.cpp` (замеры скорости $O(\log N)$).

### 3.2. Связи между компонентами

```text
[ main.cpp ]
     |
     +---> [ menu.cpp ] (Интерфейс пользователя)
     |
     +---> [ tests.cpp ] / [ benchmark.cpp ] (Проверка и замеры)
     |
     v
[ Set.hpp ] (Абстрактное множество)
     |
     | хранит как приватное поле (композиция)
     v
[ AVLTree.hpp ] (Низкоуровневое АВЛ-дерево)
     |
     | работает с
     v
[ Person.hpp ] (Пользовательские типы)
```

### 3.3. Ключевые архитектурные решения и алгоритмы
* **Композиция в `Set`:** Я не стал наследовать множество от дерева, чтобы наружу не вылезли методы вроде "извлечь поддерево" или "обход КЛП", которые нарушают логику математического множества. Множество просто держит дерево внутри себя как `private` поле.
* **Сравнение:** Шаблон не требует от типа `T` оператора `==`. Равенство двух элементов проверяется только через `operator<` (если a не меньше b, и b не меньше a, значит они равны).
* **Балансировка:** При изменении структуры пересчитывается баланс-фактор (разница высот левого и правого поддеревьев). Если он выходит за `[-1; 1]`, делается один из четырех поворотов (LL, RR, LR, RL) за $O(1)$.
* **Удаление узла с двумя потомками:** Если нужно удалить узел с двумя ветками, я нахожу минимальный элемент в его правом поддереве, аккуратно отцепляю его снизу и ставлю на место удаляемого узла. Так мы не ломаем структуру дерева.
* **map / where / reduce:** Реализованы безопасно, через готовый обход дерева (LKP), без прямого вмешательства в указатели.

## 4. Функциональные требования

**К АВЛ-дереву:**
* Вставка элемента с автоматическим сохранением баланса ($O(\log N)$). Защита от вставки дубликатов.
* Удаление узла с пересчетом высот ($O(\log N)$).
* Итеративный поиск элемента.
* 6 видов обхода в глубину (ЛКП, ПКЛ, КЛП, КПЛ, ЛПК, ПЛК).
* Функциональные операции: `map` (преобразование), `where` (фильтрация), `reduce` (свертка). Выкидывают `std::runtime_error`, если дерево пустое.
* Извлечение глубокой копии поддерева.

**К Множеству:**
* Добавление, удаление, проверка наличия элемента.
* Операции алгебры множеств: объединение ($A \cup B$), пересечение ($A \cap B$), разность ($A \setminus B$).
* Проверка подмножества ($A \subseteq B$).

**К системе в целом:**
* Полное отсутствие утечек памяти (соблюдение Правила пяти для всех классов). Подтверждено тестами (`MemoryTracker`) и утилитой Valgrind.
